Q: Can I build a karpathy.ai-style site and host it on GitHub Pages?
A: YES. Emphatically yes. karpathy.ai is the textbook GitHub-Pages use case.

Karpathy's own words (literally in his page source, bottom of the page):
   "0 frameworks were used to make this simple responsive website because I am
    becoming seriously allergic to 500-pound websites. This one is pure HTML and
    CSS in two static files and that's it."

So the entire site is:
   - index.html        (all the content/markup)
   - style.css         (all the styling, ~330 lines)
   - assets/           (images: profile pic, logos, talk thumbnails, svg icons)

That is EXACTLY what GitHub Pages serves best: static files, no build step,
no server, no database. Free hosting, HTTPS included, custom domain supported.

1. ANATOMY OF karpathy.ai  (how it is constructed)
--------------------------------------------------------------------------------
Tech stack: Plain HTML5 + CSS3. No JS framework, no build tool, no CSS framework
(no Bootstrap/Tailwind). One small vanilla-JS snippet for email reveal.

LAYOUT TECHNIQUE:
  - A reusable ".container" centered wrapper (max-width 970px on desktop).
  - A 12-column CSS GRID system built by hand:
        .row { display: grid; grid-template-columns: repeat(12, 1fr); }
        children use grid-column: span N;  (e.g. span 6 = half width)
  - Responsive via @media queries at 991px / 768px breakpoints:
        on mobile, columns collapse to "span 12" (full width, stacked).
  - NO JavaScript needed for responsiveness — pure CSS grid + media queries.

PAGE SECTIONS (top to bottom), each is just a <div class="container">:
  1. HEADER (#dhead)
        - Left: round profile photo (border-radius makes it a circle)
        - Right: <h1> name, <h2> italic tagline, row of social icon links (svg)
        - Email icon that reveals address on click (rot13 obfuscation vs spambots)
  2. <hr> gradient divider
  3. TIMELINE / HISTORY (#history)  <-- the signature visual element
        - A vertical timeline. Each job/edu = ".entry row":
             .timespan  (years, right-aligned, grey)   span 1
             .ico       (a small logo + a "dot" on a vertical line)  span 1
             .desc      (paragraph describing the role)  span 10
        - The vertical line is just `border-left` on .ico; the dots are
          absolutely-positioned little circles (.entry-dot).
  4. BIO (short paragraph)
  5. FEATURED TALKS (#featured-talks)
        - A grid of cards (".card", span 3 desktop / span 6 mobile),
          each = thumbnail image + caption, linking to YouTube/podcast.
  6. PUBLICATIONS list
        - Each ".pub": colored left-border block with
             .pub-title (linked), .pub-venue (green), .pub-authors
  7. MISC / UNSORTED  (a simple <ul> of links)
  8. Footer whitespace + the rot13 email <script>.

KEY CSS PATTERNS WORTH STEALING:
  - Circular avatar:  width/height fixed + border-radius: 50%.
  - Gradient <hr>:    linear-gradient transparent->dark->transparent.
  - Card hover-less simplicity, subtle borders (#ddd), light grey panels (#eee).
  - Typography: system "sans-serif", 16px base, line-height 1.4, color #333.
  - Italic muted subtitle (h2 color #999).
  - Everything is mobile-first-ish via two clean breakpoints. No magic.

WHY IT WORKS / DESIGN PHILOSOPHY (worth copying):
  - Minimalism. Loads instantly. Accessible. Ages well. Zero maintenance.
  - Content-first: it's basically an interactive resume + portfolio.
  - DRY: one .container, one .row grid reused everywhere. YAGNI in the flesh.

4. HOW TO HOST ON GITHUB PAGES (step-by-step, do this AFTER building)
--------------------------------------------------------------------------------
OPTION A — User/Org site (cleanest URL: https://<username>.github.io):
  1. Create a repo named EXACTLY:  <your-github-username>.github.io
     (e.g. raghavchalapathy.github.io)
  2. Put index.html + style.css + assets/ at the repo ROOT.
  3. git init, add, commit, push to the 'main' branch.
  4. Repo -> Settings -> Pages -> Source: "Deploy from a branch" ->
     Branch: main, Folder: / (root) -> Save.
  5. Wait ~1 min. Site goes live at https://<username>.github.io
  6. Add a .nojekyll file at root (avoids Jekyll mangling any _underscored files).

OPTION B — Project site (URL: https://<username>.github.io/<repo>):
  - Same as above but repo can be named anything (e.g. "profile-website").
  - Site serves under a subpath, so use RELATIVE asset paths (e.g. "assets/..",
    not "/assets/..") so images resolve correctly. (Good practice anyway.)

CUSTOM DOMAIN (optional, if you own e.g. raghav.ai like karpathy owns karpathy.ai):
  1. Buy domain from a registrar (Namecheap, Cloudflare, Google Domains, etc).
  2. Add a file named "CNAME" at repo root containing just:  raghav.ai
  3. At your DNS provider, add records:
        - Apex domain (raghav.ai): 4x A records to GitHub Pages IPs:
              185.199.108.153
              185.199.109.153
              185.199.110.153
              185.199.111.153
          (and AAAA records for IPv6 if you want — GitHub publishes these)
        - www subdomain: CNAME record -> <username>.github.io
  4. Settings -> Pages -> Custom domain -> enter raghav.ai -> Save.
  5. Tick "Enforce HTTPS" (free TLS cert via GitHub/Let's Encrypt; takes a few
     mins to provision). Done — https://raghav.ai is live.

DEPLOY UPDATES: just `git push`. Pages rebuilds automatically. No CI needed.
